# Org from ERP, project teams, leads, side-column charts — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Large orgs stay readable.
- The org (people and project teams) is drafted from ERP by the owner's Nikxel and refined by the owner in an Org tab.
- The Team view shows one team at a time, and team leads see only their teams.
- Pie and line charts sit in the wide-screen side columns, with the detailed days in the center.

**Architecture:**
- **Where the org comes from:** an owner or admin clicks "Build org from ERP…" in their Nikxel. Nikxel reads ERP over the existing session: employees, managers, titles, projects, project managers, and who had tasks on which project in the last 90 days.
- **AI step:** the AI writes a one-line description per project and a short "works on" note per person.
- **Import:** Nikxel POSTs a draft to `/api/org/import`. The server stores ERP-sourced facts next to the owner's edits; edits always win, so a re-import never undoes them.
- **Team access:** a team is an ERP project. Its leads see that team's days, and owner and admins see every team.
- **Dashboard:** the dashboard adds the Org tab, a team picker, and three-column charts.

**Tech Stack:** Swift (`src/`), TypeScript/Electron (`windows/`), Node 22 + Express 5 + better-sqlite3 (`cloud/server`), React 18 + Vite + Tailwind 4 (`cloud/dashboard`).

**Spec:** the user's request of 2026-11-21 (this session):
1. Owners and admins manage teams (teams on a project), because showing everyone's work in the Team view is too much for big orgs.
2. Add pie charts and line charts, placed in the left and right empty columns, with the center column for the detailed info.
3. Pull projects from the user's ERP connection.
4. An Org management tab, filled by AI from ERP as much as it can, which the owner then refines.

Answers:
- Leads see their own team, owner and admins see all teams, and members see only themselves.
- The import is a button in the owner's or an admin's Nikxel.
- ERP people who haven't joined appear as "not joined" with an invite button.
- One team per ERP project.

A probe against the user's ERP on 2026-11-21 found 88 projects and 42 employees, all in a single department called "Administration". So departments are useless for grouping people, and project task assignments are the real signal.

## Global Constraints

- Every `src/*.swift` change gets the same change in `windows/` in the same commit (memory: mirror-swift-changes-to-windows).
- **Roles:** org roles stay `owner | admin | member`. Lead is per team (`project_members.role = 'lead'`). Team access:
  - owner and admin see every team;
  - a lead sees the teams they lead;
  - a member sees only their own days.
- **Import body:** `POST /api/org/import`, device bearer, accepted only when the device's user is owner or admin. Shape:
  `{ people: [{ erp_id, name, email, title, manager_erp_id, note }], projects: [{ erp_id, name, description, active, members: [{ erp_id, lead: bool }] }] }`
- **Re-import never overrides a manual edit:**
  - a member the owner removed stays removed (`removed = 1`);
  - a lead set or unset by hand keeps its manual value;
  - a renamed project keeps its manual name;
  - a project the owner archived stays archived.
- **A person matches a dashboard user** by lowercase email. The owner can also link them by hand.
- **Nothing ERP-derived leaves Nikxel without a confirmation dialog.** The dialog states what will be sent ("42 people, 31 active projects, names, work emails, titles, managers").
- **Layout:** at widths ≥ 1280px the Team page uses three columns: left 280px, center 640px, right 280px. The charts sit in the side columns and stay sticky. Below 1280px, the charts stack above the center column.
- **Charts:** hand-written SVG with no new dependencies. Each is `role="img"` with an `aria-label`, has a text legend, and has an empty state. Required charts:
  - a pie of time by type;
  - a pie of time by project, for the selected team (by member) or, for "All", by project;
  - a line chart of hours per day over the last 14 days, one line per person (top 5 plus "Others").
- **The lafda look stays** (tokens, fonts and components from `cloud/dashboard/src/index.css` and `ui.jsx`).
- New dependencies: none.

## Review Focus

- **A lead opens `#team` for a team they don't lead, or calls `/api/rollup?team=<id>` directly:** 403. Tested in Task 1.
- **The owner removes a member, then re-imports from ERP:** the member stays removed. The owner renames a project, then re-imports: the name stays. Tested in Task 1.
- **The import is posted by a member's device:** 403. Tested in Task 1.
- **ERP is reachable but returns no employees (permissions):** the import still sends projects, and the dialog says 0 people. Tested in Task 2.
- **The width is exactly 1280px, or 375px:** no horizontal scroll, and the charts don't overlap the center column. Checked by screenshot in Task 4.

### Task 1: Server — org model, import, management routes, team-scoped access

**Files:**
- Modify: `cloud/server/db.js`. Add these tables:
  - `org_people (id TEXT PK, org_id, erp_id INTEGER, name, email, title, manager_erp_id INTEGER, note, user_id TEXT NULL, linked_by_hand INTEGER DEFAULT 0, UNIQUE(org_id, erp_id))`
  - `org_projects (id TEXT PK, org_id, erp_id INTEGER, name, name_by_hand INTEGER DEFAULT 0, description, active INTEGER, archived INTEGER DEFAULT 0, UNIQUE(org_id, erp_id))`
  - `project_members (project_id, person_id, role TEXT CHECK(role IN ('lead','member')), role_by_hand INTEGER DEFAULT 0, removed INTEGER DEFAULT 0, PRIMARY KEY(project_id, person_id))`
- Create: `cloud/server/org.js`. Pure functions over the db, unit-tested: `importOrg(db, orgId, body)`, `orgView(db, orgId)`, `teamsFor(db, orgId, userId, role) -> [{id, name}]` and `teamMemberUserIds(db, projectId) -> [userId]`.
- Modify: `cloud/server/routes.js`. Add the routes:
  - `POST /org/import` (deviceAuth, plus a role check from memberships: owner or admin, otherwise 403)
  - `GET /org` (owner/admin) returns `orgView`, which has people with `joined` (user_id set) and projects with members
  - `PATCH /org/projects/:id {name?, archived?}` (owner/admin)
  - `PUT /org/projects/:id/members/:personId {role: 'lead'|'member'}` (owner/admin; sets `role_by_hand=1, removed=0`)
  - `DELETE /org/projects/:id/members/:personId` (owner/admin; sets `removed=1`)
  - `PATCH /org/people/:id {user_id|null}` (owner/admin; manual link, sets `linked_by_hand=1`)
  - `GET /teams` (any signed-in user) returns `teamsFor`
  - `GET /rollup?team=<projectId>`. It is open to owner and admin (all teams) and to leads (only teams they lead), and returns only that team's members' days. Without `team`, it keeps today's owner/admin-only behaviour.
- Test: `cloud/server/org.test.js`, `cloud/server/routes.test.js`

**Interfaces:**
- Produces: the routes above. Each `orgView` person is `{id, erp_id, name, email, title, manager_erp_id, note, user_id, joined}`. Each project is `{id, erp_id, name, description, active, archived, members:[{person_id, name, role, removed, joined}]}`.

### Task 2: Desktop — "Build org from ERP…" (mac + windows)

**Files:**
- Modify: `src/ERP.swift` and `windows/src/main/system/erp.ts`. Add `orgSnapshot() -> OrgSnapshot` (TS: async). It reads:
  - `hr.employee`: `name, work_email, job_title, parent_id, user_id`;
  - `project.project`: `name, user_id` (manager), `active`;
  - `project.task` with `write_date` in the last 90 days: `project_id, user_ids, name`.
  Members per project are the employees whose `user_id` appears in that project's task `user_ids`. The project manager becomes `lead: true`. A project is `active` when it had tasks in the window. The snapshot keeps up to 15 task names per project, for the AI step only; they are never sent. On any failure it returns empty lists.
- Modify: `src/CloudSync.swift` and `windows/src/main/system/cloudSync.ts`. Add `importOrg(_ body: [String: Any], post:) -> Bool`, which POSTs `/api/org/import` with the device token.
- Create: `src/OrgImport.swift` and `windows/src/main/system/orgImport.ts`. The flow:
  1. Take the snapshot.
  2. Run one AI prompt through the existing `MOMGenerator.runPrompt(_, kind: "org-import")`. It returns JSON `{projects:{<erp_id>: "<one-line description>"}, people:{<erp_id>: "<works-on note>"}}`, built from project names, task names and titles. If the JSON doesn't parse, it falls back to empty notes.
  3. Build the import body.
  4. Show the confirmation dialog listing the counts and fields.
  5. POST, then show "Org sent — refine it in the dashboard's Org tab" or the server's error ("Only the owner or an admin can do this").
